## 纪律区（每版必读，违反即为重复故障）

| # | 纪律 | 来源 |
|---|---|---|
| ⑤ | **「在渲染树中」不等于「可见」。** 浮层类组件（popover/menu/tooltip/dropdown）的用例必须至少覆盖一条「逃逸出滚动/裁切容器」的契约（宿主 = `document.body` 或等价 Portal），并在实机走查中用截图确认它**真的在屏幕像素上出现过** | v0.34.3（D59） |
| ⑥ | **用户给的「阈值」要先问是「偏好」还是「症状描述」**（「超过三个会挤压」可能是她窗口只放得下三个）。歧义时按「症状描述」解读并让机制自适应 —— 它同时满足两种解读 | v0.34.3（D58） |
| ⑦ | **白名单 / 枚举只许有一个事实源。** 合法值必须导出为常量数组 + `isXxx()` 守卫，全仓只许调用守卫，并有用例断言「常量与守卫逐字一致」；**表驱动穷尽用例必须遍历枚举全体**，不许挑选「看起来够了」的几个 | v0.34.3（D61） |
| ⑧ | **夹具形状必须复刻生产形状。** 凡「声明式清单 → 消费者」链路，回归用例必须**直接取清单本身**作为输入，并**先断言前提**（前提变了要响亮失败，而不是静默失效） | v0.34.3（D62） |
| ⑨ | **静默退化是复合缺陷的粘合剂。** 凡「取不到值就原样保留 / 返回空」的容错路径，必须在**诊断通道**留一句人话 —— 否则三重静默叠加起来，用户只看到「数据为空」 | v0.34.3（D62） |
| ⑭ | **接线类代码必须有「接线契约」用例。** 补语义用例只能证明函数是对的；必须再断言**调用点存在**且**顺序正确**（如「注入宿主版本」必须早于「首次扫描」）。反例 D79：`setHostVersion()` 全函数正确，但**没有任何调用点** | v0.35.0（D79） |
| ⑮ | **契约测试要区分「形状校验」与「语义校验」。** 只断言 `REGEX.test()` 等于没测 `.exec()` 的**捕获下标**；把分组写成非捕获组 `(?:…)` 而下游按下标取值 = 未爆弹。反例 D78：`ENGINE_RANGE_RE` 的非捕获组让 `r[1]` 取到主版本号数字 → 兼容判定恒 `false` | v0.35.0（D78） |
| ⑯ | **补丁版也必须留用例矩阵。** 任何版本（含 `x.y.z` 补丁版）收尾都必须留 `testcases/00-cumulative-matrix.md` —— 哪怕只写「一行总量 + 本版新载体清单」。否则下一个版本**丧失逐版归因能力** | v0.35.0（L-35-02） |
| ⑰ | **每个版本收尾必须落 git，且必须请用户确认。** v0.34.3 与 v0.34.4 **均未 commit**（`HEAD` 停在 tag `v0.34.2`），使三版测试改动混在同一工作树，`git status` 无法分离归属 —— 这是「逐版归因不可复原」的直接原因。收尾动作固定为：**请用户确认 → commit → tag → push** | v0.35.0（L-35-02） |
