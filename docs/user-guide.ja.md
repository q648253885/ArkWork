[简体中文](./user-guide.zh-CN.md) | [English](./user-guide.en.md) | [한국어](./user-guide.ko.md)

ArkWork はローカルファーストの AI Agent デスクトップワークベンチです。ReAct 推理ループ（Reason → Act → Observation）を完全に可視化し、すべてのステップをリアルタイムで確認でき、いつでも一時停止・介入でき、タスク全体を追跡・再利用できます。

## 1. インストール

### 方法 A：インストーラーをダウンロード（推奨）

本リポジトリの [Releases](../../releases) ページから、お使いのプラットフォーム用パッケージをダウンロードしてください：

| プラットフォーム | ファイル |
|------------------|----------|
| macOS | `ArkWork-x.x.x-x64.dmg` |
| Windows | `ArkWork-Setup-x.x.x-x64.exe` |

**macOS**：dmg を開き、ArkWork を「アプリケーション」にドラッグします。
**Windows**：インストーラーを実行し、画面の指示に従います。

### 方法 B：ソースから実行

必要環境：Node.js ≥ 18、npm。

```bash
git clone https://github.com/<your-account>/ArkWork.git
cd ArkWork/app
npm install
npm run dev          # 開発モードで起動
npm run build:mac    # macOS 用パッケージを作成
npm run build:win    # Windows 用パッケージを作成
```

## 2. 初回起動：モデルの設定

ArkWork には LLM が同梱されていません。利用には最低 1 つのプロバイダー登録が必要です：

1. `⌘,` で設定を開く
2. **モデル** タブ → **モデルを追加** をクリック
3. 以下を入力：
   - **id / name**：任意の識別子と表示名
   - **kind**：プロバイダー種別 — `openai` / `anthropic` / `ollama` / `vllm`
   - **baseURL**：API エンドポイント（OpenAI 互換エンドポイントなら何でも可）
   - **apiKey**：API キー（Ollama などローカルモデルでは空欄可）
4. **テスト** をクリックして接続を確認し、保存
5. 入力欄下部のモデルチップから、いつでもモデルを切り替えられます

> ヒント：OpenAI 互換エンドポイント（DeepSeek、MiniMax、vLLM、LM Studio など）は `openai` 種別で追加できます。

## 3. 画面と基本概念

```
┌──────┬──────────────────────────┬───────────┐
│ 左ナビ │     中央ステージ           │  右ドック   │
│      │     （会話メイン）          │ (タスク情報)│
└──────┴──────────────────────────┴───────────┘
```

| 概念 | 説明 |
|------|------|
| **ワークスペース** | 1 フォルダ = 1 の独立したワークスペース。タスク・記憶・ナレッジベースはすべて内部に保存されます |
| **タスク** | Agent との一連のセッション。入力・記憶・ステップ履歴・成果物を完全保存し、続きの対話やエクスポートに対応 |
| **エージェント** | 人格設定を持つ実行者。用途ごとに作成し、スキルを割り当てられます |
| **スキル** | Agent が呼び出せる原子能力（shell、ファイル入出力、Web 取得など）。マーケットから追加も可能 |
| **プラグイン** | ArkWork 自体を拡張する部品。コマンド・右側ドックのパネル・コードビューを提供できます |
| **対話フロー** | 三層の情報アーキテクチャ：本文（あなたのメッセージと返信）、プロセス（思考 / ツール呼び出し / 観察）、折りたたみ可能なプロセスグループ |
| **右側ドック** | オンデマンドでスライド表示される検査エリア：やること / コンテキスト / ファイル / ログ / ブラウザ / ターミナル |
| **チェックポイント** | 毎ターン自動保存。任意のイテレーションへワンクリックでロールバック |
| **プレビューウィンドウ** | Markdown / Web / コード / 画像 / 表のフローティングプレビュー |

### メモリ L1 – L4

記憶は「タスク内 → ワークスペース → ワークスペース横断」へと層ごとに沈殿します。一次証拠は下位層に残り、長期内容だけがタスク終了時の整理によってキュレーション層へと導出・書き込みされます。

| レイヤー | 内容 |
|----------|------|
| **L1 ワーキングメモリ** | 現在のタスクのターン単位の項目（メッセージ / 思考 / ツール観察）。唯一の一次証拠であり、蒸留しても削除されません |
| **L2 ファイルメモリ** | あふれた大きな結果とステップ成果物をファイル化し、必要時に読み戻します。コンテキストに常駐しません |
| **L3a キュレーションメモリ** | プロジェクト記憶はワークスペースに（プロジェクトと共に移動）、ユーザー選好はグローバル Agent 空間に（ワークスペース横断で共有） |
| **L3b アーカイブ** | タスク終了時に L1 を検索可能な履歴項目として保管。原本も保持され、再確認・検索が可能 |
| **L4 ユーザープロファイル** | ワークスペース横断の長期選好。初回 / 24 時間 / 5 タスクの周期で一括合成され、毎回書き直されません |

> タスク終了時の整理（収尾巩固）：タスク終了時に、モデルが L1 / L2 から長期内容を抽出し、まず保留領域に入れて次回実行時に反映します。失敗時は何も書き込みません。

## 4. 日常的な使い方

### タスクの作成と実行

1. 下部の入力欄（Composer）に依頼を入力して Enter
2. Agent が Reason → Act ループを開始。対話フローに各ステップの推論とツール呼び出しがリアルタイム表示されます
3. いつでも **一時停止 / 再開 / キャンセル** 可能
4. 完了後、右側ドックでやること・成果物ファイル・コンテキスト・ログを確認できます

### 並列実行

同じターン内で互いに依存しない作業は同時に開始されます。1 回の推論で複数のツール呼び出しが並列実行され、進捗はそれぞれの次元で独立に表示され、上書きされません。分割可能なサブタスクはサブエージェントに委譲され並列処理され、各サブエージェントが独自のステップ履歴と成果物を持ちます。書き込み後に読み取るといった前後依存は、競合を避けるため引き続き直列で実行されます。

### コンテキストの制御

右側ドックの **コンテキスト** パネルは読み取り専用で、このタスクに注入されたナレッジベース / メモリの断片とコンテキスト使用量を表示します。メモリ項目はメモリセンターで編集できます。

### 任意のイテレーションへのロールバック

毎イテレーションにチェックポイントがあります。タスク詳細で対象を選ぶと、その時点まで巻き戻ります。

### 成果物のプレビュー

会話内の成果物カードをクリックすると、フローティングプレビュー（Markdown / ブラウザ / コードハイライト / 画像 / 表）で開きます。ドラッグして独立ウィンドウ化も可能です。

## 5. ファイルワークベンチ

ワークスペースのファイルをアプリ内で直接開き、編集し、保存できます：

- **名前でジャンプ**：QuickOpen（`⌘P`）でファイルをすばやく特定。右側ドックの **ファイル** タブではワークスペースのディレクトリツリー全体を閲覧でき、クリックするとエディタで開きます
- **エディタ**：構文ハイライト、マルチカーソル、検索と置換、行操作に対応。保存は原子的書き込み（先に一時ファイルへ書き、その後置き換え）で、中途半端なファイルが残りません
- **競合バナー**：ディスク上のファイルが外部で変更されると競合バナーが表示されます。差分を比較し、自分の変更を残すかディスク版を採用するかを選択でき、黙って上書きされることはありません
- **境界**：ワークスペース内のファイルは読み書き可能。ワークスペース外のファイル（絶対パスで参照した場合など）は読み取り専用で開き、理由を表示したうえで書き込みは拒否されます

## 6. エージェントとスキル

- **エージェント作成**：左ナビのエージェントページ → 新規。名前・人格を記入し、割り当てるスキルにチェック
- **エージェント切替**：エージェントページまたはタスクヘッダーから切替。切替後はそのエージェントの右側ドック設定が自動的に適用されます
- **内蔵スキル**：shell ターミナル、ファイル読み書き/編集、glob/grep 検索、fetch-url、web-search、session-search、kb-search など 10 以上
- **スキルの由来**：内蔵 / マーケット / インポート済みの 3 グループに分類されます。zip から取り込む場合は zip 全体の内容（すべての `.md` とサブディレクトリのファイル）がスキルフォルダに展開されます
- **権限モード**：全ツール呼び出しは権限ゲートを通過します。`Shift+Tab` で権限モードを循環切替でき、許可ポリシーは「設定と権限」で調整できます

## 7. プラグイン

プラグインは ArkWork 自体の能力を拡張します。コマンド、パネル、コードビューを提供できます。

1. 能力ページの **プラグイン** タブで新規作成・インストール（zip パッケージを選択）・アンインストールができます
2. インストール前には、そのプラグインが申請する権限と機能一覧が提示され、確認して初めてディスクに書き込まれます
3. 提供されたコマンドは QuickAction（`⌘K`）に現れ、そのまま起動できます。提供されたパネルとビューは右側ドックのタブに表示されます
4. コードプラグインは独立したホストプロセスで実行され、機能許可リストの制約下に置かれます。検証の失敗やクラッシュはそのプラグイン自身にのみ影響し、他のプラグインは巻き込まれません
5. アンインストール時には「プラグインデータ削除」を選択でき、そのプラグインの私有キーバリューもあわせて消去されます

## 8. ワークベンチ

ワークベンチは設定能力のホストです。ある働き方をワークベンチ Profile として宣言し、切り替えることで画面レイアウトと有効化される能力が変わります。

1. 各 Profile はレイアウト、有効化するプラグインとスキル、右側ドックのタブ、テーマなどを宣言します。内蔵のプリセットを複製して手を加えることもできます
2. 新規作成と編集はウィザード方式で、手順に沿ってレイアウトと能力を選ぶだけで、JSON を手書きする必要はありません
3. 有効化すると宣言内容が適用されます。「何を宣言したか」と「実際に何が有効になったか」が同一ページで対照表示され、劣化や検証上の問題はその場でバナーにより説明されます
4. Profile と有効化レポートはいずれもエクスポート・インポートでき、同じ働き方を複数のマシン間で同期できます

## 9. ナレッジベース

ローカル文書を検索可能な私有ナレッジに変えます：

1. 左ナビの **ナレッジベース** パネルを開く
2. ローカルファイルを取り込む（PDF / Word / Markdown / テキストなどの一般的な形式に対応）
3. 自動的にチャンク分割され、全文インデックスが作成されます。文書には「解析中 / インデックス済み / 失敗」の 3 状態があり、失敗時はワンクリックで再試行できます
4. 「セッション単位 + グローバル単位」の二層スイッチを備えています。タスクで有効にすると、Agent が kb-search スキルで検索・参照できます

## 10. MCP とスキルマーケット

- **MCP**：設定で stdio タイプの MCP Server を追加すると、そのツールが Agent に注入されます
- **スキルマーケット**：内蔵マーケットパネルでコミュニティスキルを閲覧・インストール。インストール済みスキルは各エージェントの選択肢に表示されます

## 11. 自動化タスク

左ナビの **オートメーション** パネル：

1. 新規作成し、アラーム式の頻度選択またはカスタム cron 式で周期を定義（例：`0 9 * * 1-5` = 平日毎日 9:00）
2. タスク内容と対象ワークスペースを記入
3. 定刻に自動実行され、実行記録は対応するタスクの対話フローに書き戻され、パネルでも確認できます

## 14. 設定と権限

設定ページはタブで整理されています：**モデル / ワークスペース / ナレッジ / 外観 / 詳細**。

- **モデル**：既定モデルと予備モデルの選択、API キーの設定。OpenAI、Anthropic、およびローカルの Ollama / vLLM などの互換エンドポイントに対応
- **ワークスペース**：現在のワークスペースの切替（1 フォルダ = 1 ワークスペース）、既定のナレッジベースとファイル無視ルール
- **外観**：ライト / ダーク / システムに従う、および文字サイズ・密度。切替は即時反映され、再起動は不要
- **権限ルール**：由来 4 段階（管理者 / このワークスペース / プロジェクト設定 / 個人設定）で表示され、個別に有効・無効化できます。ヒット状況はログで確認できます
- **この選択を記憶**：傍受オーバーレイの「この選択を記憶」は、その決定を 1 つのルールとして書き込みます（既定ではこのワークスペースに記録）。次回の同種の呼び出しでは中断されません
- **詳細**：ログ / グラフ診断、圧縮戦略の読み取り専用表示、実験的スイッチ

## 15. パフォーマンスとローカルストレージ

ArkWork は独立した GPU を持たないマシンに向けた性能上の取捨選択を行いつつ、ローカルファーストを維持しています：

- **動きの規律**：透明度変化と単色呼吸といった低コストな効果のみを残し、ぼかし・移動・継続再描画のアニメーションは使いません
- **半透明ガラスなし**：背景ぼかしは全面的に撤廃し、オーバーレイは単色レイヤーに変更。GPU のない環境での毎フレーム合成コストを避けます
- **自動降格**：システムで「動きを減らす」が有効な場合は自動的に降格します。ソフトウェアレンダリングを検出した場合も性能降格モードに入り、画面はただちに静止します
- **データディレクトリ**：開発時は `app/.dev-data` にリダイレクト。パッケージ時は OS のユーザーデータディレクトリ配下に置かれ、アプリデータのルートはその中の `arkwork-data` です
  - macOS：`~/Library/Application Support/ArkWork/`
  - Windows：`%APPDATA%\ArkWork\`
  - Linux：`~/.config/ArkWork/`
- **プライバシー**：テレメトリは一切収集しません。会話・記憶・ナレッジベースのインデックスはすべてローカルに保存されます。LLM Provider との通信は設定した API エンドポイントに限られ、API キーはローカルの設定ファイルにのみ保存されます

## 16. よくある質問

**Q：モデルの「テスト」に失敗する**
baseURL（`/v1` サフィックスの要否）、apiKey、ネットワークのプロキシ設定を確認してください。ローカルモデルはサーバー起動を確認してください（Ollama の既定は `http://127.0.0.1:11434`）。

**Q：macOS で一部フォルダへのアクセスを拒否される**
macOS のプライバシー保護（TCC）によるものです。「システム設定 → プライバシーとセキュリティ → ファイルとフォルダ」で ArkWork に許可を与えるか、書類/ダウンロードなど許可済みディレクトリにワークスペースを置いてください。

**Q：会話内のファイルリンクが開かない**
ワークスペース外のファイルは読み取り専用で開き、理由が表示されます。ワークスペース内のファイルでも開けない場合は、そのファイルが移動または削除されていないか確認してください。

**Q：タスクデータはどこに保存される？消えることは？**
すべてローカルに永続化されます（上記参照）。アプリをアンインストールしてもディレクトリは削除されません。定期的なバックアップを推奨します。

**Q：完全にリセットするには？**
アプリを終了し、データディレクトリ内の `arkwork-data` フォルダを削除すると初期状態に戻ります（全タスクと設定が消えるため事前バックアップを）。

**Q：対応しているプロバイダーは？**
OpenAI、Anthropic、Ollama、vLLM、および OpenAI 互換エンドポイント全般（DeepSeek、MiniMax、SiliconFlow など）。
