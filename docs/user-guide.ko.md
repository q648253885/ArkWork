# ArkWork 사용자 가이드 (한국어)

[简体中文](./user-guide.zh-CN.md) | [English](./user-guide.en.md) | [日本語](./user-guide.ja.md)

ArkWork은 로컬 퍼스트 AI Agent 데스크톱 워크벤치입니다. ReAct 추론 루프(Reason → Act → Observation)를 완전히 시각화하여, 모든 단계를 실시간으로 확인하고 언제든 일시정지·개입할 수 있으며, 작업 전체를 추적하고 재사용할 수 있습니다.

## 1. 설치

### 방법 A: 설치 패키지 다운로드 (권장)

이 저장소의 [Releases](../../releases) 페이지에서 플랫폼에 맞는 패키지를 다운로드하세요:

| 플랫폼 | 파일 |
|--------|------|
| macOS | `ArkWork-x.x.x-x64.dmg` |
| Windows | `ArkWork-Setup-x.x.x-x64.exe` |

**macOS**: dmg를 열고 ArkWork를 '응용 프로그램'으로 드래그합니다.
**Windows**: 설치 프로그램을 실행하고 안내에 따릅니다.

### 방법 B: 소스에서 실행

필요 환경: Node.js ≥ 18, npm.

```bash
git clone https://github.com/<your-account>/ArkWork.git
cd ArkWork/app
npm install
npm run dev          # 개발 모드로 실행
npm run build:mac    # macOS용 패키지 빌드
npm run build:win    # Windows용 패키지 빌드
```

## 2. 첫 실행: 모델 설정

ArkWork에는 LLM이 내장되어 있지 않습니다. 최소 1개의 프로바이더를 등록해야 합니다:

1. `⌘,` 로 설정 창을 엽니다
2. **모델** 탭 → **모델 추가** 클릭
3. 다음 항목을 입력:
   - **id / name**: 식별자와 표시 이름
   - **kind**: 프로바이더 유형 — `openai` / `anthropic` / `ollama` / `vllm`
   - **baseURL**: API 엔드포인트 (OpenAI 호환 엔드포인트라면 무엇이든 가능)
   - **apiKey**: API 키 (Ollama 같은 로컬 모델은 비워 두어도 됨)
4. **테스트** 를 클릭해 연결을 확인한 후 저장
5. 입력창 하단의 모델 칩에서 언제든 모델을 전환할 수 있습니다

> 팁: OpenAI 호환 엔드포인트(DeepSeek, MiniMax, vLLM, LM Studio 등)는 `openai` 유형으로 추가할 수 있습니다.

## 3. 화면 구성과 핵심 개념

```
┌──────┬──────────────────────────┬───────────┐
│ 왼쪽  │       중앙 스테이지        │  오른쪽 독  │
│ 내비  │      (대화 메인)           │ (작업 정보) │
└──────┴──────────────────────────┴───────────┘
```

| 개념 | 설명 |
|------|------|
| **워크스페이스** | 폴더 1개 = 독립된 워크스페이스 1개. 작업·기억·지식 베이스가 모두 그 안에 저장됩니다 |
| **태스크** | Agent와의 한 세션. 입력·기억·단계 이력·산출물을 완전 저장하며, 이어하기와 내보내기를 지원합니다 |
| **에이전트** | 페르소나를 가진 실행자. 용도별로 만들고 스킬을 바인딩할 수 있습니다 |
| **스킬** | Agent가 호출하는 원자 단위 기능(shell, 파일 입출력, 웹 가져오기 등). 마켓에서 추가 설치도 가능 |
| **플러그인** | ArkWork 자체를 확장하는 부품: 명령, 오른쪽 독 패널, 코드 뷰를 제공할 수 있습니다 |
| **대화 흐름** | 3계층 정보 구조: 본문(사용자 메시지와 응답), 과정(생각 / 도구 호출 / 관찰), 접을 수 있는 과정 그룹 |
| **오른쪽 독** | 필요할 때 슬라이드로 나오는 검사 영역: 할 일 / 컨텍스트 / 파일 / 로그 / 브라우저 / 터미널 |
| **체크포인트** | 매 턴 자동 저장. 원하는 반복 시점으로 원클릭 롤백 |
| **미리보기 창** | Markdown / 웹 / 코드 / 이미지 / 표의 플로팅 미리보기 |

### 메모리 L1 – L4

기억은 '작업 내 → 워크스페이스 → 워크스페이스 간'으로 층층이 축적됩니다. 1차 증거는 아래층에 남고, 장기 내용은 마무리 정리가 큐레이션 계층에 도출·기록할 때만 씁니다.

| 계층 | 내용 |
|------|------|
| **L1 작업 기억** | 현재 작업의 턴별 항목(메시지 / 생각 / 도구 관찰). 유일한 1차 증거이며 증류해도 삭제되지 않습니다 |
| **L2 파일 기억** | 넘친 큰 결과와 단계 산출물을 파일로 남기고 필요할 때 다시 읽어 들입니다. 컨텍스트에 상주하지 않습니다 |
| **L3a 큐레이션 기억** | 프로젝트 기억은 워크스페이스에(프로젝트를 따라감), 사용자 선호는 전역 Agent 공간에(워크스페이스 간 공유) |
| **L3b 아카이브** | 작업 마무리 시 L1을 검색 가능한 기록 항목으로 보관하고 원본도 유지합니다. 다시 조회하고 검색할 수 있습니다 |
| **L4 사용자 프로필** | 워크스페이스 간 장기 선호. 최초 / 24시간 / 작업 5개 주기로 일괄 합성하며 매번 다시 쓰지 않습니다 |

> 마무리 정리: 작업이 끝나면 모델이 L1 / L2에서 장기 내용을 추출해 먼저 대기 영역에 넣고 다음 실행에서 반영하며, 실패하면 아무것도 쓰지 않습니다.

## 4. 일상적인 사용

### 태스크 만들고 실행하기

1. 하단 입력창(Composer)에 요청을 입력하고 Enter
2. Agent가 Reason → Act 루프를 시작합니다. 대화 화면에 각 단계의 추론과 도구 호출이 실시간 표시됩니다
3. 언제든 **일시정지 / 재개 / 취소** 가능
4. 완료 후 오른쪽 독에서 할 일·산출물·컨텍스트·로그를 확인합니다

### 병렬 실행

같은 턴에서 서로 의존하지 않는 작업은 동시에 시작됩니다: 하나의 추론에서 여러 도구 호출이 병렬로 실행되고 진행 상황은 각자의 차원에서 독립적으로 표시되며 서로 덮어쓰지 않습니다. 분할 가능한 하위 작업은 서브 에이전트에 위임되어 병렬로 처리되고, 각 서브 에이전트는 독립된 단계 흐름과 산출물을 가집니다. 선후 의존 관계(쓰기 후 읽기)는 경합을 피하기 위해 여전히 직렬로 실행됩니다.

### 컨텍스트 제어

오른쪽 독의 '컨텍스트' 패널은 이 작업에 주입된 지식 베이스 / 기억 조각과 컨텍스트 사용량을 읽기 전용으로 보여줍니다. 기억 항목은 메모리 센터에서 편집할 수 있습니다.

### 원하는 반복 시점으로 롤백

매 반복마다 체크포인트가 생성됩니다. 작업 상세에서 대상 체크포인트를 선택하면 그 시점으로 되돌아갑니다.

### 산출물 미리보기

대화 속 산출물 카드를 클릭하면 플로팅 미리보기(Markdown / 브라우저 / 코드 하이라이트 / 이미지 / 표)로 열립니다. 드래그해서 독립 창으로 분리할 수도 있습니다.

## 5. 파일 워크벤치

워크스페이스 파일을 앱 안에서 바로 열고 편집하고 저장합니다:

- **이름으로 이동**: QuickOpen(`⌘P`)으로 파일을 빠르게 찾습니다. 오른쪽 독의 '파일' 탭에서 워크스페이스 전체 디렉터리 트리를 볼 수 있고, 클릭하면 편집기에서 열립니다
- **편집기**: 구문 강조, 다중 커서, 찾기 바꾸기, 줄 조작을 지원합니다. 저장은 원자적 쓰기(임시 파일에 쓴 뒤 교체)라서 반쪽짜리 파일이 남지 않습니다
- **충돌 배너**: 디스크의 파일이 외부에서 바뀌면 충돌 배너가 나타납니다. 차이를 비교하고 내 변경을 유지하거나 디스크 버전을 선택할 수 있으며, 조용히 덮어쓰지 않습니다
- **경계**: 워크스페이스 안의 파일은 읽기·쓰기가 가능합니다. 워크스페이스 밖의 파일(예: 절대 경로로 참조)은 읽기 전용으로 열리고 이유가 표시되며, 쓰기는 거부됩니다

## 6. 에이전트와 스킬

- **에이전트 생성**: 왼쪽 내비의 에이전트 페이지 → 새로 만들기. 이름·페르소나를 입력하고 바인딩할 스킬 선택
- **에이전트 전환**: 에이전트 페이지나 작업 헤더에서 전환합니다. 전환하면 해당 에이전트의 오른쪽 독 설정이 자동으로 적용됩니다
- **내장 스킬**: shell 터미널, 파일 읽기/쓰기/편집, glob/grep 검색, fetch-url, web-search, session-search, kb-search 등 10여 개
- **스킬 출처**: '내장 / 마켓플레이스 / 가져옴' 세 그룹으로 분류됩니다. zip 가져오기 시 zip 전체 내용(모든 `.md` 파일과 하위 디렉터리)이 스킬 폴더로 풀립니다
- **권한 모드**: 모든 도구 호출은 권한 게이트의 보호를 받습니다. `Shift+Tab`으로 권한 모드를 순환 전환하며, 허용 정책은 '설정 및 권한'을 참고하세요

## 7. 플러그인

플러그인은 ArkWork의 기능을 확장합니다: 명령, 패널, 코드 뷰를 제공할 수 있습니다.

1. 기능 페이지의 '플러그인' 탭에서 새로 만들기, 설치(zip 선택), 제거
2. 설치 전에 먼저 신청한 권한과 기능 목록을 나열하며, 확인한 뒤에야 디스크에 씁니다
3. 제공한 명령은 QuickAction(`⌘K`)에서 바로 실행할 수 있습니다. 제공한 패널과 뷰는 오른쪽 독의 탭에 나타납니다
4. 코드 플러그인은 별도 호스트 프로세스에서 실행되고 기능 허용 목록의 제약을 받습니다: 검증 실패나 크래시는 해당 플러그인에만 영향을 주고 다른 플러그인은 영향을 받지 않습니다
5. 제거 시 '플러그인 데이터 삭제'를 선택해 그 플러그인의 전용 키-값까지 함께 정리할 수 있습니다

## 8. 워크벤치

워크벤치는 구성 기능의 호스트입니다: 하나의 작업 방식을 워크벤치 Profile로 선언하면, 전환만으로 인터페이스 레이아웃과 활성화되는 기능이 바뀝니다.

1. 각 Profile은 레이아웃, 활성화할 플러그인과 스킬, 오른쪽 독 탭, 테마 등을 선언합니다. 기본 제공 방안을 복사한 뒤 필요에 맞게 고칠 수 있습니다
2. 새로 만들기와 편집은 마법사 방식으로 진행되어, 단계별로 레이아웃과 기능을 선택하며 JSON을 직접 쓸 필요가 없습니다
3. 활성화하면 선언한 내용이 적용됩니다. '선언한 내용'과 '실제 적용된 내용'을 같은 페이지에서 대조 표시하고, 저하와 검증 문제는 해당 위치에 배너로 설명합니다
4. Profile과 활성화 보고서 모두 내보내기·가져오기가 가능해, 여러 대의 기기에서 같은 작업 방식을 동기화할 수 있습니다

## 9. 지식 베이스

로컬 문서를 검색 가능한 사유 지식으로 바꿉니다:

1. 왼쪽 내비에서 **지식 베이스** 패널 열기
2. 로컬 파일 가져오기(PDF / Word / Markdown / 텍스트 등 일반 형식 지원)
3. 자동으로 청크 분할되고 전체 텍스트 색인이 생성됩니다. 문서는 '파싱 중 / 색인됨 / 실패' 세 가지 상태를 가지며 실패는 원클릭으로 재시도할 수 있습니다
4. '세션 수준 + 전역 수준' 이중 스위치를 제공합니다: 작업에서 활성화하면 Agent가 kb-search 스킬로 검색·인용할 수 있습니다

## 10. MCP와 스킬 마켓

- **MCP**: 설정에서 stdio 유형의 MCP Server를 추가하면 해당 도구가 Agent에 주입됩니다
- **스킬 마켓**: 내장 마켓 패널에서 커뮤니티 스킬을 탐색·설치합니다. 설치된 스킬은 각 에이전트의 선택 목록에 나타납니다

---

## 11. 자동화 작업

왼쪽 내비의 **자동화** 패널:

1. 자동화를 새로 만들고 알람 방식의 주기 선택 또는 사용자 정의 cron 표현식으로 정의(예: `0 9 * * 1-5` = 평일 매일 9시)
2. 작업 내용과 대상 워크스페이스를 입력
3. 예정 시각에 자동 실행되며, 실행 기록은 해당 작업의 대화 흐름에 기록되고 패널에서도 확인할 수 있습니다

## 12. 인터페이스 언어 변경

**설정 → 모양** 에서 선택할 수 있습니다:

- 简体中文 (중국어, 기본값)
- English (영어)
- 日本語 (일본어)
- 한국어

첫 설치 시 시스템 언어를 자동 감지합니다. 전환은 즉시 적용되며 재시작이 필요 없습니다.

## 14. 설정 및 권한

설정 페이지는 탭으로 구성됩니다: **모델 / 워크스페이스 / 지식 / 모양 / 고급**.

- **모델**: 기본 및 대체 모델 선택, API Key 설정. OpenAI, Anthropic과 로컬 Ollama / vLLM 등 호환 엔드포인트 지원
- **워크스페이스**: 현재 워크스페이스 전환(폴더 1개 = 워크스페이스 1개), 기본 지식 베이스와 파일 무시 규칙
- **모양**: 라이트 / 다크 / 시스템 따르기와 글자 크기·밀도. 전환은 즉시 적용되며 재시작이 필요 없습니다
- **권한 규칙**: 출처 4단계(관리자 / 이 워크스페이스 / 프로젝트 구성 / 개인 구성)로 표시되며, 규칙별로 켜고 끌 수 있고 적용 여부는 로그에서 확인할 수 있습니다
- **이 선택 기억**: 차단 오버레이의 '이 선택 기억'은 이번 결정을 하나의 규칙으로 기록합니다(기본은 이 워크스페이스에 기록). 다음에 같은 종류의 호출은 더 이상 방해하지 않습니다
- **고급**: 로그 / 그래프 진단, 압축 전략 읽기 전용 표시와 실험용 스위치

## 15. 성능과 로컬 저장소

ArkWork은 독립 GPU가 없는 기기를 위해 성능을 절충하면서도 로컬 퍼스트를 유지합니다:

- **동작 규율**: 투명도 변화와 단색 호흡 같은 저렴한 효과만 남기고, 흐림·이동·지속적 다시 그리기 애니메이션은 사용하지 않습니다
- **반투명 유리 없음**: 배경 흐림을 전면 제거하고 오버레이는 단색 레이어로 바꾸어, GPU가 없는 환경에서 프레임마다 합성하는 비용을 피합니다
- **자동 저하**: 시스템에서 '동작 줄이기'를 켜면 자동으로 저하되고, 소프트웨어 렌더링이 감지되면 성능 저하 모드로 들어가 인터페이스가 즉시 정지합니다
- **데이터 디렉터리**: 개발 시에는 `app/.dev-data`로 리디렉션되고, 패키지 빌드에서는 시스템 사용자 데이터 디렉터리에 저장되며 앱 데이터 루트는 그 안의 `arkwork-data`입니다
  - macOS: `~/Library/Application Support/ArkWork/`
  - Windows: `%APPDATA%\ArkWork\`
  - Linux: `~/.config/ArkWork/`
- **프라이버시**: 어떤 텔레메트리도 업로드하지 않습니다. 대화·기억·지식 베이스 색인은 모두 로컬에 저장됩니다. LLM Provider와의 통신은 설정한 API 엔드포인트로만 이루어지며, API Key는 로컬 설정 파일에만 저장됩니다

## 16. 자주 묻는 질문

**Q: 모델 '테스트'가 실패합니다**
baseURL(`/v1` 접미사 필요 여부), apiKey, 네트워크 프록시 설정을 확인하세요. 로컬 모델이라면 서버 실행 여부를 확인하세요(Ollama 기본값 `http://127.0.0.1:11434`).

**Q: macOS에서 일부 폴더 접근이 거부됩니다**
macOS 프라이버시 보호(TCC) 때문입니다. '시스템 설정 → 개인정보 보호 및 보안 → 파일 및 폴더'에서 ArkWork에 권한을 부여하거나, 문서·다운로드처럼 이미 허용된 디렉터리에 워크스페이스를 두세요.

**Q: 대화의 파일 링크가 열리지 않나요?**
워크스페이스 밖의 파일은 읽기 전용으로 열리고 이유가 표시됩니다. 경로가 워크스페이스 안인데도 열리지 않으면 파일이 이동되었거나 삭제되었는지 확인하세요.

**Q: 작업 데이터는 어디에 저장되나요? 사라질 수 있나요?**
모두 로컬에 영구 저장됩니다(위 참조). 앱을 제거해도 해당 디렉터리는 삭제되지 않습니다. 정기적인 백업을 권장합니다.

**Q: 완전히 초기화하려면?**
앱을 종료한 뒤 데이터 디렉터리의 `arkwork-data` 폴더를 삭제하면 초기 상태로 돌아갑니다(모든 작업과 설정이 지워지므로 먼저 백업하세요).

**Q: 어떤 프로바이더를 지원하나요?**
OpenAI, Anthropic, Ollama, vLLM, 그리고 OpenAI 호환 엔드포인트 전반(DeepSeek, MiniMax, SiliconFlow 등).
