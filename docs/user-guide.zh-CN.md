[English](./user-guide.en.md) | [日本語](./user-guide.ja.md) | [한국어](./user-guide.ko.md)

## 1. 安装

### 方式一：下载安装包（推荐）

前往本仓库的 [Releases](../../releases) 页面，下载对应平台的安装包：

| 平台 | 文件 |
|------|------|
| macOS | `ArkWork-x.x.x-x64.dmg` |
| Windows | `ArkWork-Setup-x.x.x-x64.exe` |

**macOS**：打开 dmg，将 ArkWork 拖入「应用程序」即可。
**Windows**：运行安装器，按提示完成安装。

### 方式二：从源码运行

前置要求：Node.js ≥ 18、npm。

```bash
git clone https://github.com/<your-account>/ArkWork.git
cd ArkWork/app
npm install
npm run dev          # 开发模式启动
npm run build:mac    # 打包 macOS 安装包
npm run build:win    # 打包 Windows 安装包
```

## 2. 首次启动：配置模型

ArkWork 本身不内置大模型，需要接入至少一个 LLM Provider 才能工作：

1. 按 `⌘,`（或点击 设置）打开设置窗口
2. 进入 **模型** 标签页 → 点击 **添加模型**
3. 填写：
   - **id / name**：自定义标识与显示名
   - **kind**：服务商类型，支持 `openai` / `anthropic` / `ollama` / `vllm`
   - **baseURL**：API 地址（OpenAI 兼容端点均可）
   - **apiKey**：密钥（本地模型如 Ollama 可留空）
4. 点击 **测试** 确认连通后保存
5. 在输入框底部的模型 chip 上可随时切换当前使用的模型

> 提示：任何 OpenAI 兼容端点（DeepSeek、MiniMax、vLLM、LM Studio 等）都可以用 `openai` 类型接入。

## 3. 界面与核心概念

```
┌──────┬──────────────────────────┬───────────┐
│ 左栏 │        主对话区            │  右侧坞    │
│ 导航 │      （CenterStage）       │(RightDock)│
└──────┴──────────────────────────┴───────────┘
```

| 概念 | 说明 |
|------|------|
| **工作区 Workspace** | 一个文件夹 = 一个独立工作区。任务、记忆、知识库均落盘在工作区内，互不干扰 |
| **任务 Task** | 一次完整的 Agent 会话。保存输入、记忆、步骤流与产物文件，支持续聊与导出 |
| **智能体 Agent** | 带人格设定的执行者。可为不同场景创建不同 Agent 并绑定技能 |
| **技能 Skill** | Agent 可调用的原子能力（shell、文件读写、网页抓取等），也可从市场安装 |
| **插件 Plugin** | 扩展 ArkWork 本身的部件：可贡献命令、右侧坞面板与代码视图 |
| **对话流** | 三层信息架构：正文（你的消息与回复）、过程（思考 / 工具调用 / 观察）与可折叠的过程组 |
| **右侧坞 RightDock** | 按需滑出的检查区：清单 / 上下文 / 文件 / 日志 / 浏览器 / 终端 |
| **检查点 Checkpoint** | 每轮自动存档，出问题可一键回滚到任意迭代 |
| **预览窗 PreviewWindow** | 浮窗预览 Markdown / 网页 / 代码 / 图片 / 数据表产物 |

### 记忆 L1 – L4

记忆按「任务内 → 工作区 → 跨工作区」逐层沉淀：一手证据留在下层，长期内容只由收尾巩固推导写入策展层。

| 层级 | 内容 |
|------|------|
| **L1 工作记忆** | 当前任务的逐轮条目（消息 / 思考 / 工具观察），是唯一的一手证据，蒸馏不会删除它 |
| **L2 文件记忆** | 溢出的大结果与步骤产物落成文件，按需读回，不常驻上下文 |
| **L3a 策展记忆** | 项目记忆落工作区（随项目走）；用户偏好留在全局 Agent 空间（跨工作区共享） |
| **L3b 档案** | 任务收尾时把 L1 归档成可检索的历史条目，原始条目同时保留，可回查可检索 |
| **L4 用户画像** | 跨工作区的长期偏好，按周期（首次 / 24 小时 / 5 个任务）批量合成，不做每次重写 |

> 收尾巩固：任务结束时由模型从 L1 / L2 提炼长期内容，先进暂存区、下次运行才生效；失败时一个字都不写。

## 4. 日常使用

### 创建并运行任务

1. 在底部输入框（Composer）输入需求，回车发送
2. Agent 开始 Reason → Act 循环：主对话区实时展示每步推理与工具调用
3. 需要介入时随时 **暂停 / 恢复 / 取消**
4. 任务结束后可在右侧坞查看清单、产物文件、上下文与日志

### 并行执行

同一轮里互不依赖的工作会被并发发起：同一 Agent 一次推理中可触发多个工具调用并行执行，进度按各自的维度独立展示、互不覆盖；遇到可拆分的子任务会委派给子 agent 并行处理，每个子 agent 有独立的步骤流与产出。前后依赖（写入后再读取）仍按串行执行，避免竞态。

### 控制上下文

右侧坞「上下文」面板只读展示本任务注入的知识库 / 记忆片段与上下文占用；记忆条目可在记忆中心编辑。

### 回滚到任意迭代

每次迭代都有检查点。在任务详情中选择目标检查点即可回滚，之后的分支重新开始。

### 预览产物

点击对话中的产物卡片，会在浮窗中打开对应渲染器（Markdown / 浏览器 / 代码高亮 / 图片 / 表格），支持拖拽为独立浮窗。

## 5. 文件工作台

工作区文件在应用内直接打开、编辑与保存：

- **按名字跳转**：用 QuickOpen（`⌘P`）快速定位文件；右侧坞「文件」标签里可浏览整棵工作区目录树，点击即在编辑器打开
- **编辑器**：支持语法高亮、多光标、查找替换与行操作；保存为原子写入（先写临时文件再替换），不会留下半截文件
- **冲突提示**：磁盘文件被外部改动时弹出冲突横幅，可对比差异，选择保留我的改动或采用磁盘版本，不会静默覆盖
- **边界**：工作区内的文件可读可写；工作区外的文件（例如以绝对路径引用）以只读方式打开并标出原因，写入会被拒绝

## 6. 智能体与技能

- **创建 Agent**：左栏进入智能体页 → 新建，填写名称、人格描述，勾选要绑定的技能
- **切换 Agent**：在智能体页或任务头部切换；切换后自动应用该 Agent 的右侧坞偏好
- **内置技能**：shell 终端、文件读写/编辑、glob/grep 检索、fetch-url 网页抓取、web-search 联网搜索、session-search 会话检索、kb-search 知识库检索等 10+
- **技能来源**：按「内置 / 市场 / 已导入」三组分类；从 zip 导入时整个 zip 内容（所有 `.md` 与子目录文件）都会解压到技能文件夹
- **权限模式**：每个工具调用受权限门禁保护，可用 `Shift+Tab` 循环切换权限模式；放行策略见「设置与权限」

## 7. 插件

插件扩展 ArkWork 的能力：可贡献命令、面板与代码视图。

1. 在能力页的「插件」标签里新建、安装（选择 zip 包）与卸载
2. 安装前会先列出它申请的权限与能力清单，确认后才落盘
3. 贡献的命令会进入 QuickAction（`⌘K`）可直接触发；贡献的面板与视图出现在右侧坞的标签里
4. 代码插件在独立的宿主进程中运行并受能力白名单约束：校验失败或崩溃只影响它自己，其他插件不受牵连
5. 卸载时可选「删除插件数据」，连同该插件的私有键值一起清理

---

## 8. 工作台

工作台是配置能力的宿主：把一套工作方式声明成工作台 Profile，切换即改变界面布局与启用能力。

1. 每个 Profile 声明布局、启用的插件与技能、右侧坞标签与主题等；可从内置方案复制一份再按需改造
2. 新建与编辑走向导化配置，按步骤选择布局与能力，不需要手写 JSON
3. 激活后会应用其声明；「声明了什么」与「实际生效了什么」在同一页对照呈现，降级与校验问题就地以横幅说明
4. Profile 与激活报告都可导出、导入，便于在多台机器之间同步同一套工作方式

## 9. 知识库

把本地文档变成 Agent 可检索的私有知识：

1. 左栏进入 **知识库** 面板
2. 导入本地文件（支持 PDF / Word / Markdown / 文本等常见格式）
3. 应用会自动切块并建立全文索引；文档有「解析中 / 已索引 / 失败」三态，失败可一键重试
4. 提供「会话级 + 全局级」双层开关：在任务中启用后，Agent 可通过 kb-search 技能检索引用

## 11. 自动化任务

左栏进入 **自动化** 面板：

1. 新建自动化，支持闹钟式频率选择或自定义 cron 表达式（如 `0 9 * * 1-5` 工作日每天 9 点）
2. 填写任务内容与目标工作区
3. 到点自动执行，执行记录会回写到对应任务的对话流，面板中也可查看

## 14. 设置与权限

设置页按标签组织：**模型 / 工作区 / 知识 / 外观 / 高级**。

- **模型**：选择默认与备用模型、配置 API Key；支持 OpenAI、Anthropic 与本地 Ollama / vLLM 等兼容端点
- **工作区**：切换当前工作区（一个文件夹即一个工作区）、默认知识库与文件忽略规则
- **外观**：浅色 / 深色 / 跟随系统与字号密度；切换立即生效，无需重启
- **权限规则**：按来源四级展示（管理员 / 本工作区 / 项目配置 / 个人配置），可逐条启用与停用，命中情况在日志里可查
- **记住此选择**：拦截浮层上的「记住此选择」会把这次决定写成一条规则（默认记到本工作区），下次同类调用不再打断你
- **高级**：日志 / 图谱诊断、压缩策略只读展示与实验性开关

## 15. 性能与本地存储

ArkWork 面向没有独立显卡的机器做了性能取舍，同时保持本地优先：

- **动效纪律**：只保留透明度变化与纯色呼吸这类廉价效果，不用模糊、位移与持续重绘的动画
- **无毛玻璃**：背景模糊已全面移除，遮罩改为纯色分层，避免无 GPU 环境下的逐帧合成开销
- **自动降级**：系统开启「减少动态效果」时会自动降级；检测到软件渲染时也会进入性能降级模式，界面立即静止
- **数据目录**：开发态重定向到 `app/.dev-data`；打包态在系统用户数据目录，应用数据根为其中的 `arkwork-data`
  - macOS：`~/Library/Application Support/ArkWork/`
  - Windows：`%APPDATA%\ArkWork\`
  - Linux：`~/.config/ArkWork/`
- **隐私**：不上传任何遥测数据；对话、记忆与知识库索引都落本地；与 LLM Provider 的通信仅限你配置的 API 端点，API Key 仅存储在本机配置文件

## 16. 常见问题

**Q：模型「测试」失败？**
检查 baseURL 是否正确（注意是否需要 `/v1` 后缀）、apiKey 是否有效、网络是否需要代理。本地模型确认服务已启动（如 Ollama 默认 `http://127.0.0.1:11434`）。

**Q：macOS 上访问某些文件夹被拒绝？**
这是 macOS 隐私保护（TCC）限制。在「系统设置 → 隐私与安全性 → 文件与文件夹」中给 ArkWork 授权，或将工作区放在「文档」「下载」等已授权目录。

**Q：点击对话里的文件打不开？**
工作区外的文件会以只读方式打开并标出原因；若路径在工作区内仍打不开，请检查文件是否已被移动或删除。

**Q：任务数据存在哪里？会不会丢？**
全部落盘在本地用户数据目录（见上文），卸载应用不会删除该目录；建议自行定期备份。

**Q：如何彻底重置？**
退出应用后删除用户数据目录中的 `arkwork-data` 文件夹即可恢复初始状态（会清除所有任务与配置，请先备份）。

**Q：支持哪些模型服务商？**
OpenAI、Anthropic、Ollama、vLLM，以及一切 OpenAI 兼容端点（DeepSeek、MiniMax、硅基流动等）。
